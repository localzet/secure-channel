# Secure Channel

Экспериментальный клиент TypeScript и серверный адаптер для обмена запросами и ответами через WebSocket с взаимной TLS-аутентификацией. Выпуск сертификатов, шлюз и правила доступа сервисов реализуются отдельно.

[English documentation](README.md)

## Установка и проверка

```sh
npm install @localzet/secure-channel
# В исходном репозитории: Node.js 22+, OpenSSL для тестов
npm ci
npm test
```

## Клиент

```ts
import { readFileSync } from 'node:fs'
import { SecureChannelClient } from '@localzet/secure-channel'

const client = new SecureChannelClient({
  url: 'wss://gateway.example.com',
  serviceId: 'billing',
  certificate: readFileSync(process.env.CLIENT_CERT!, 'utf8'),
  privateKey: readFileSync(process.env.CLIENT_KEY!, 'utf8'),
  caCertificate: readFileSync(process.env.CHANNEL_CA!, 'utf8'),
})
await client.connect()
try {
  const payload = await client.request({ route: 'health', payload: {} })
  console.log(payload)
} finally {
  client.disconnect()
}
```

`request()` возвращает содержимое ответа; тайм-аут, разрыв соединения или ошибка сервера отклоняют Promise. Параллельные вызовы `connect()` используют одну попытку соединения. Неожиданный разрыв запускает переподключение; явный `disconnect()` отменяет его и завершает ожидающие запросы ошибкой. Если ответ потерян, операция могла уже выполниться: для повторов изменяющих запросов нужны прикладные ключи идемпотентности.

Разрешены только URL `https:` и `wss:`. Проверка сертификата сервера обязательна. Без `caCertificate` используется доверенное хранилище Node.js. Ранее отсутствие CA отключало проверку — это небезопасное поведение исправлено. Метки времени и nonce формирует клиент; переданные пользователем заголовки не могут их переопределить.

## Сервер

Создайте HTTPS-сервер с `requestCert: true`, `rejectUnauthorized: true` и доверенными клиентскими CA. Подключите `WebSocketServer` с явным `maxPayload`, затем вызовите `bindSecureChannelServer({ wss, verifyClient, onRequest })`. Адаптер отклоняет соединения без проверенного клиентского сертификата. Через `verifyClient` ограничьте разрешённые идентификаторы сервисов: доверие к CA само по себе не разрешает доступ каждому подписанному сертификату. Исключения обработчика возвращают обобщённую ошибку без внутренних подробностей.

Защита от повторов отклоняет повторные nonce, устаревшие метки времени и запросы при заполненном кеше. По умолчанию допустимое расхождение часов — 30 секунд, TTL nonce — 60 секунд, ёмкость — 10 000. TTL должен быть не меньше удвоенного расхождения часов. Кеш действует в пределах одного адаптера одного процесса; репликам нужна общая защита либо раздельная маршрутизация сертификатов/соединений. Ограничения соединений, размера сообщений и частоты запросов настраиваются на входе отдельно. Обработчики должны проверять прикладные данные.

## Разработка

`npm test` собирает пакет и выполняет сетевые тесты с временными сертификатами вне репозитория. `npm run build` создаёт `dist/`. CI не публикует пакет в реестр. Перед обновлением проверьте совместимость потребителей с исправлениями безопасности.
